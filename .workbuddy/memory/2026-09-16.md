## 内容情报 Agent 立项并交付（packages/agent）

用户以「聘请 CEO」的方式要求：制作一个 Agent 负责「每日抖音 Top10 抓取 → 四维拆解打标签 → 输出趋势报告」这个任务。此前该任务由 server 的 cron + runDaily 脚本承担，缺乏判断、质检与自愈能力。

### 实现
新增零依赖包 `packages/agent`（Node 22 内置模块，与 core 同规范），六层闭环：

- `src/sense.js` 感知：真实源探测（8s 超时）、今日报告新鲜度、近 7 天缺口、历史题材序列、长期经验读数
- `src/plan.js` 规划：动作序列 + 人类可读的 rationale；修复策略 `planRepair` 只在「重跑确实能改善」时才触发（数据源类问题重跑无意义，只登记告警）
- `src/act.js` 执行：重试 2 次 + 线性退避，每动作留痕（耗时/结果/错误）
- `src/evaluate.js` 质检：8 项规则 → 0–100 健康分 → A/B/C/D；修复阈值 85
- `src/memory.js` 记忆：agent_runs / agent_findings / agent_memory 三表，置信度 0.6/0.4 加权融合
- `src/brief.js` 简报：CEO 三分钟读完（干成没 / 什么问题 / 下一步）
- `src/agent.js` 编排：runAgent / planOnly / getSnapshot / learn / startDaemon

### 接入
- server 新增 `/api/agent/{status,plan,run,brief,memory,findings,runs,stats}`；每日 09:00 cron 由 runDaily 切换为 runAgent；boot 补数据也走 Agent
- 新增零构建控制台 `agent-console/index.html`，STATIC_MAP 挂 `/agent/`（**改完必须重启服务**，启动时解析）
- 根 package.json 加 `agent:*` 脚本；test 脚本改为两包 glob

### 验证
- 测试 core 22 + agent 17 = 39/39 通过
- CLI plan/run/status/brief 实跑；人为删除 2026-09-12 数据后，Agent 自动检出缺口并补齐（自愈验证通过）
- 当前健康分 85 / B 级，唯一扣分项是「非真实数据源」（未配 DOUYIN_API_KEY），预期内

### 文档
新建 `AGENT.md`（Agent 契约：使命/决策规则/质检规则/记忆模型/接口/失败处理/已知限制）；README 加「内容情报 Agent」章节、架构图加智能层、目录与 API 表更新。

## 真实数据源接入（用户追问"真实数据源怎么接"）

### 实测结论（2026-09-16 亲测，重要长期事实）
- `iesdouyin.com/web/api/v2/hotsearch/billboard/word/` → **200，50 条真实热搜词 + hot_value**，免 Key 稳定可用
- `iesdouyin.com/aweme/v1/web/hot/search/list/` → **403 blocked**（旧代码 HOT_VIDEO_URL 正指向它，通道 A 早已失效，是个真 bug）
- `iesdouyin.com/web/api/v2/hotsearch/billboard/aweme/` → 200 但数组为空，视频榜已关闭
- 抖音开放平台只能拿自己账号数据，**拿不到全站榜单**，别浪费时间申请

### 做的改动
- `douyin.js`：修正失效端点 + 新增 `fetchHotWords()`（真实热搜词，含 rank/word/hotValue/labelText(新/热/爆)/url）
- `composite.js`：改为 custom → douyin → simulated 链式；**无论走哪条通道都附带真实热搜词**（含降级时）
- `custom.js`（新）：任意 HTTP JSON 数据源通用适配器，env 配置 `CUSTOM_API_URL` + `CUSTOM_API_MAP` 字段映射，支持 `a.b.c` 嵌套与 `arr[].field` 数组语法，POST/自定义 header/Bearer 全支持
- `report/generate.js`：`audienceInsight.realHotWords` + `hotWordsSource` + 顶层 `hotWords`；Markdown 新增「抖音实时热搜榜」段落（标注真实来源与抓取时间）
- `evaluate.js`：`LIVE_SOURCES = {douyin, custom}`，只有 simulated 才扣「非真实数据」15 分
- `sense.js`：probeLiveSource 支持 custom 通道
- `server`：`GET /api/hotwords`（实时，不走缓存）
- 控制台「今日受众偏爱」加真实热搜 chips

### 验证
- `/api/hotwords` 返回 50 条真实词（如「巨人之旅330」1210万）；报告 `realHotWords` 10 条、`hotWordsSource=douyin`、markdown 含热搜段
- 全量测试 39/39；三端 + /agent/ 全 200

### 给用户的三条路径
A 官方热搜词（0 元，已启用）｜B 第三方数据商（新抖/蝉妈妈/飞瓜，数千元/年，拿视频级数据的唯一合规途径）｜C 自建采集（不推荐，封 IP + 合规灰区）。自定义适配器让 B 变成填配置而非写代码。

## 数据源接通（CEO 追问「怎么接」）

### 关键认知：数据是分两层的，别混为一谈
- **话题层**（今日热搜词 TOP50）→ **0 元、真实、已接通**（iesdouyin，实测 50 条）
- **视频层**（Top10 播放/互动/时长）→ 抖音已关闭全部免签名通道，**只能买**
- 实测：`hot/search/list/` 403、`billboard/aweme/` 200 但空数组、vvhan/alapi 等聚合站返回的全是热搜词不是视频

### 本轮代码改动
1. `custom.js` 新增 **`CUSTOM_API_AUTH`**（bearer/appcode/raw/none）—— 原来写死 Bearer，
   **阿里云市场/京东万象这类国内云市场全用 `APPCODE`，根本接不进来**。这是本轮最有价值的修复。
2. `custom.js` 新增**字段映射体检**：播放量/时长/话题三个维度全为 0 时自动告警，
   防「接口通了但字段没对上、静默产出废数据」。
3. `douyin.js` `getJSON` 友好报错：403 空响应从「Unexpected end of JSON input」
   改成「HTTP 200 空响应（多半是反爬拦截）」。
4. `douyin.js` 热搜加**备用通道** `60s.viki.moe/v2/douyin`，主通道挂了自动降级并带 warnings。
   **已实测降级成功**（用隔离副本把主通道指向 127.0.0.1:1，channel 正确切到 mirror）。

### 新增产物
- `packages/core/bin/datasource-check.js` + `npm run datasource:check` —— 一条命令打印
  当前配置 / 热搜通道 / 视频榜三通道实测 / 结论与下一步。
- `packages/core/test/custom.test.js` —— **10 个用例，用本地 mock HTTP 服务端到端验证**，
  证明接数据商的代码链路是通的（含 APPCODE 认证、POST 占位符、arr[].field、废数据拦截）。
  **以后配不通，问题必在 URL/Key/映射三处，不用怀疑代码。**
- `DATA_SOURCING.md` —— 执行手册：两层数据区分、三条路对比（含门牌号与价格）、接线四步、
  字段映射语法、排查清单、验收标准（4 条）。
