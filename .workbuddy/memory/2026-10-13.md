## 踩坑（写脚本分析 title.js 时）

- **`extractFeatures()` 返回的 `hits` 是 Set，不是普通对象** → `JSON.stringify` 会显示成 `{}`，
  看起来像「特征全没命中」。我一度误判为打分器坏了。**统计要用 `.size` / `.has()`**。
- **`scoreTitle(title, baseline)` 在 `baseline.size < 10` 时直接返回 0 分 + `features: []`**
  （设计如此：「基准样本不足」）。用少量标题（如 ps=8）做抽样会误以为打分失效。
  → 排查打分器时，基准样本必须 ≥10 条。
- 已复核无 bug，打分区分度正常：「跟着AI教学能否实现薯条自由？」46分C /
  「【4K修复】为什么没人做这个？3个方法」64分B / 「今天吃了顿饭」14分D。

# 同日 03:0x · 落地「契约先行」多 Agent 协作机制

用户要求：AI 承担前端开发之外的全部工作（需求拆解/接口与数据模型设计/实现联调/自动化测试/构建部署），
自己只写前端页面与交互。要职责边界、协作顺序、交接中间物、契约先行+变更同步机制。

## 产出（全部零第三方依赖，仅 Node22 内置模块）
- `COLLAB.md`：方案文档（职责边界表 / 7 步流水线含 3 道门禁 / 交接中间物清单 / 变更同步五步 / 6 条铁律）
- `contracts/api.json`：24 个真实端点契约单一真源（status: draft/frozen），初版由现有 server 实现反推
- `contracts/fixtures.json` + `scripts/mock-server.mjs`（:8788）：契约驱动 mock，draft 端点返回 409
- `scripts/gen-types.mjs` → `types/api.d.ts`：18 模型 / 24 端点，**禁止手改**
- `scripts/contract-check.mjs`：frozen 端点必须字段齐 + 有 mock，否则命令失败（开工门禁）
- `scripts/contract-diff.mjs`：对比归档判定 BREAKING/兼容，自动写 CHANGELOG + 归档 `api-<version>.json`，有 BREAKING 退出码 2
- `scripts/contract-ack.mjs`：`contracts/.ack` 版本闸门，未同步即退出 1
- `package.json` 新增 6 个 `contract:*` 命令；`WORKFLOWS.md` 后端→前端交接改为「契约+类型+mock+变更说明」四项齐全

## 实测结果
contract:check 通过（24 frozen 全有 mock）；gen-types 生成正常；mock 服务返回 fixture、未知路径 404、端点索引正常；
ack 前报错 / ack 后放行。

## 设计要点（以后复用直接照抄）
- **契约冻结是前端开工的硬门禁**；正因契约先行，前后端可并行——前端用 mock 写完整页面，不等后端实现完
- **三道闸**：① draft 不可用（mock 返回 409）② `contract:check` ③ `.ack` 版本比对
- **变更同步五步**：改契约 bump version → `contract:diff` → `contract:types` → 前端 `contract:sync` 看到变更 → 改完 `contract:ack`
- 建议把 `contract:check` 与 `contract:sync` 挂进 CI / pre-commit，机器兜底而不靠自觉

## 前提事实
契约初版 2026-10-13.1 由现有 server 实现反推，**字段精度需阿服（后端 Agent）逐条确认后冻结**——
新增端点一律先 draft，走完流程再冻结。

# 同日 03:1x · 为每个 Agent 增加每日工作留痕

需求：结构化日志（时间/agent标识/任务名与来源/关键步骤/工具接口/结果/耗时/异常），按 agent+日期归档、可检索回溯，
写入不阻塞、失败有降级、敏感信息脱敏，并明确存储/命名/查看方式。

## 产出
- `packages/core/src/audit/logger.js`：留痕内核（零依赖）。`createLogger().task()` 返回可链式
  `step()/tool()/ok()/fail()` 的句柄；`run()` 包装器抛错自动 fail 后继续抛（**不吞异常**）；`record()` 一次性记录。
- `packages/core/bin/agentlog.js`：CLI —— `view / list / stats / add / tail`，
  支持 `--agent --date --status --last --json --root`。
- `packages/core/test/audit.test.js`：8 例（脱敏/字段完整/归档/失败记录/不吞异常/三级降级/可回溯）。
- 埋点 `packages/agent/src/agent.js`：小沸六层闭环每步 `step()`、DB 与接口调用 `tool()`、失败 `fail()` 后继续抛；
  `planOnly` 与 daemon 的 catch 同样留痕。
- `AGENT_LOGGING.md`：存储/命名/字段表/查看方式/脱敏规则 + 13 个 agentId 映射。
- `agents/scaffold.py` 的 `AGENTS_TMPL` 新增「七、工作留痕（每日必做）」（用 `{slug}` 作 agentId），重建岗位包后全员自带。
- `package.json` 新增 `log:view/list/stats/add`；`.gitignore` 加 `logs/`。

## 关键设计（复用照抄）
- 存储：`logs/agents/<agentId>/<YYYY-MM-DD>.jsonl`（**JSONL 一行一条**：追加不破坏已有内容、坏行不污染、便于 grep/流式读）
- **agentId 直接复用 `agents/<slug>` 英文目录名**（backend-dev / qa / content-strategist…），小沸 = `xiaofei`
- 三级降级：主目录 → `logs/_fallback/`（标 `degraded`+`writeError`）→ `console.error`，**绝不抛错**
- 不阻塞：调用方只入队 + `setImmediate` 异步 flush（**调用方不 await**）；`beforeExit`/`exit` 同步兜底刷写残留
- 脱敏：敏感键（token/password/secret/authorization/api_key/cookie/phone…）整值抹除、邮箱部分掩码、
  超长字符串(>500)截断、深度>6 与数组>50 截断

## 踩坑（重要）
- **`import { appendFile } from 'node:fs'` 是回调版，不是 Promise 版** → `await` 它直接抛错，
  于是全部走进降级分支、日志**根本没有落盘**（测试第一次 4/8 失败就是栽这）。
  必须 `import { appendFile } from 'node:fs/promises'`。

## 验证
全量测试 **71/71**（原 63 + 新增 8）。实跑 `agent plan` 后 `logs/agents/xiaofei/` 自动生成，
CLI `view` 能看到「步骤: 感知 → 规划 / 工具: sense.observe, plan.planActions / 耗时 / traceId」；
`view --status fail` 可定位到「阿服 story-13 email 字段校验缺失」；`stats` 出成功率与平均耗时。
