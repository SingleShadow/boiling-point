## 踩坑（写脚本分析 title.js 时）

- **`extractFeatures()` 返回的 `hits` 是 Set，不是普通对象** → `JSON.stringify` 会显示成 `{}`，
  看起来像「特征全没命中」。我一度误判为打分器坏了。**统计要用 `.size` / `.has()`**。
- **`scoreTitle(title, baseline)` 在 `baseline.size < 10` 时直接返回 0 分 + `features: []`**
  （设计如此：「基准样本不足」）。用少量标题（如 ps=8）做抽样会误以为打分失效。
  → 排查打分器时，基准样本必须 ≥10 条。
- 已复核无 bug，打分区分度正常：「跟着AI教学能否实现薯条自由？」46分C /
  「【4K修复】为什么没人做这个？3个方法」64分B / 「今天吃了顿饭」14分D。

# 同日 03:0x · 落地「契约先行」多 Agent 协作机制

用户要求：AI 承担前端开发之外的全部工作（需求拆解/接口与数据模型设计/实现联调/自动化测试/构建部署），
自己只写前端页面与交互。要职责边界、协作顺序、交接中间物、契约先行+变更同步机制。

## 产出（全部零第三方依赖，仅 Node22 内置模块）
- `COLLAB.md`：方案文档（职责边界表 / 7 步流水线含 3 道门禁 / 交接中间物清单 / 变更同步五步 / 6 条铁律）
- `contracts/api.json`：24 个真实端点契约单一真源（status: draft/frozen），初版由现有 server 实现反推
- `contracts/fixtures.json` + `scripts/mock-server.mjs`（:8788）：契约驱动 mock，draft 端点返回 409
- `scripts/gen-types.mjs` → `types/api.d.ts`：18 模型 / 24 端点，**禁止手改**
- `scripts/contract-check.mjs`：frozen 端点必须字段齐 + 有 mock，否则命令失败（开工门禁）
- `scripts/contract-diff.mjs`：对比归档判定 BREAKING/兼容，自动写 CHANGELOG + 归档 `api-<version>.json`，有 BREAKING 退出码 2
- `scripts/contract-ack.mjs`：`contracts/.ack` 版本闸门，未同步即退出 1
- `package.json` 新增 6 个 `contract:*` 命令；`WORKFLOWS.md` 后端→前端交接改为「契约+类型+mock+变更说明」四项齐全

## 实测结果
contract:check 通过（24 frozen 全有 mock）；gen-types 生成正常；mock 服务返回 fixture、未知路径 404、端点索引正常；
ack 前报错 / ack 后放行。

## 设计要点（以后复用直接照抄）
- **契约冻结是前端开工的硬门禁**；正因契约先行，前后端可并行——前端用 mock 写完整页面，不等后端实现完
- **三道闸**：① draft 不可用（mock 返回 409）② `contract:check` ③ `.ack` 版本比对
- **变更同步五步**：改契约 bump version → `contract:diff` → `contract:types` → 前端 `contract:sync` 看到变更 → 改完 `contract:ack`
- 建议把 `contract:check` 与 `contract:sync` 挂进 CI / pre-commit，机器兜底而不靠自觉
