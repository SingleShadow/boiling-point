### 架构

### 关键坑（下次直接复用）
1. **本机 bash 环境残缺**：`ls/grep/tail` 不在 PATH。Bash 工具必须先 `export PATH="/usr/bin:/bin:/usr/local/bin:$PATH"`。PowerShell 工具**输出捕获不到**，别用它做验证。
2. Node/npm 绝对路径：`C:/Users/cui/.workbuddy/binaries/node/versions/22.22.2-3/node.exe` 与同目录 `npm.cmd`。Windows 下 node 需带盘符路径 `E:/opc/...`，不能用 `/e/opc/...`。
3. npm 默认 registry 慢（每 tarball 600-900s），改用 npmmirror 镜像秒级完成（已写在 apps/web/.npmrc）。
4. uni-app 必须用 `@dcloudio/uni-app` / `uni-h5` / `vite-plugin-uni` 同为 `3.0.0-alpha-5020620260914001`（dist-tag vue3），且 **vite 锁 5.2.8**（peer 精确要求，`^5.4` 会 ERESOLVE）。
5. umi 4 缺 `@umijs/preset-react` 时 `.umirc.ts` 里写 `antd:{}` 会报 `Invalid config keys`；改用 ConfigProvider 运行时注入主题 token 规避。
6. Electron 在本环境装到的是占位二进制，GUI 无法启动 —— 桌面端类任务需提前准备「浏览器直开渲染页」的降级验证路径。
7. `node --test <dir>` 在本机不能传目录（报 MODULE_NOT_FOUND），要传 glob：`node --test packages/core/test/*.test.js`。

## 追加（19:30）：移动 App 从 uni-app(Vue3) 重写为 Taro 4 + React 18

用户要求移动端改用 React。确认方案：**Taro 4.2.1 + React 18**（uni-app 的 React 等价物，保留多端能力），**完全替换** uni-app 版（apps/mobile 已清空重建）。

### 结果
- `apps/mobile` 全新 Taro 工程：pages = index(今日) / detail(拆解详情) / report(趋势报告) / tags(标签体系) / mine(我的)，tabBar 今日·报告·我的；组件 Card/StateView/ScoreRing/TagChip/BarRow/CollapsePanel/BrandHeader/DimensionBlock
- `NODE_ENV=production taro build --type h5` 成功，产物 `apps/mobile/dist/index.html`，资源前缀 `/app/`；`/app/`、`/app/js/*`、`/app/css/*` 均 200
- 服务端 `STATIC_MAP` 改为多候选目录（apps/mobile/dist → dist/build/h5），支持换构建工具不用改代码

### 新踩的坑
1. **server 的 STATIC_MAP 在启动时解析 dist**，新产物必须重启服务才生效 —— 已记入 MEMORY.md 铁律
2. Taro `config/index.js` 的 `cssModules` 不能带 `namingPattern`/`generateScopedName`，被配置校验拦下
3. 缺 `@babel/preset-react` 时 `babel-preset-taro` 编译 JSX 报错
4. 用 `npm install --no-workspaces` 装依赖，避免影响根 monorepo；耗时约 28 分钟
