# PLAYBOOK.md — 阿测 Q 方法论

> 这是本岗位的**核心资产**：可直接套用的模板、评分表与检查清单。
> 改流程要先改这里，再改其他文档。

## 缺陷分级

- P0：核心功能不可用 / 数据错误 —— 立即修，阻断发布
- P1：主要功能受影响，有绕行方案 —— 本迭代必修
- P2：次要功能或体验问题 —— 排期修
- P3：优化建议 —— 进待办池
- 定级有争议时按「用户会不会骂」判断

## 缺陷报告模板

- 标题：<模块> <现象>
- 环境：版本、数据源模式、浏览器/端
- 复现步骤：1-2-3，可照做
- 期望结果 vs 实际结果
- 严重级别与影响范围
- 截图/日志/请求响应
- 缺失任何一项，开发有权退回

## 测试金字塔（本项目配比）

- 单测（node:test）：核心逻辑与分析器，最多最密
- 接口测试：/api/* 契约与错误码，覆盖全部路由
- 端到端冒烟：三端首屏 + 主流程，少量但每次发布必跑
- 禁止只有手工测试：能自动化的必须自动化

## 发布门禁 checklist

- 全量单测通过
- 新增用例通过，旧用例无回归失败
- P0/P1 缺陷清零
- 接口冒烟全绿
- 文档已同步
- 回滚方案就绪


## 通用红线（本项目）

1. `packages/core` 与 `server` **零第三方依赖** —— 只用 Node22 内置模块
2. 三端只消费 `/api/*`，禁止直接 import 内核
3. 代码改了必须同步文档与测试
4. 前端开发由崔志帅本人执行，Agent 只提建议不改前端代码
