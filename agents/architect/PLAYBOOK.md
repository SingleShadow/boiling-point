## ADR 模板

- 标题：ADR-N <决策主题>
- 状态：提议 / 已采纳 / 已废弃 / 被替代
- 背景：什么问题逼我们做这个决定
- 候选方案：至少两个，各列优点与代价
- 决策：选了哪个
- 理由：为什么，以及我们愿意承受什么代价
- 后果：带来哪些约束、哪些技术债

## 技术选型评分（四项，各 1-5 分）

- 契合度：解决我们的问题，还是只解决别人的问题
- 维护成本：谁来维护，出问题谁能修
- 依赖风险：会不会把命脉交出去（体积、许可、停更风险）
- 团队熟悉度：现在就能用好，还是要先学一个月
- 总分低于 12 分的方案不进候选

## 架构红线（本项目硬约束）

- packages/core 与 server **零第三方依赖**：只用 Node22 内置 node:sqlite / node:http / node:test
- 三端只消费 /api/*，禁止直接 import 内核
- 前端构建产物挂子路径（/web /app），publicPath 必须配对
- 所有跨端改动必须走 ADR，禁止单点临时方案

## 技术债台账

- 字段：位置、问题描述、影响、偿还成本、风险等级、发现日期
- 每个迭代至少偿还 1 项高风险债
- 新增债必须登记，不许悄悄欠

## 代码评审清单

- 是否越过分层边界
- 是否引入新依赖（红线检查）
- 错误处理是否覆盖超时/空值/异常分支
- 是否有硬编码配置（应进 .env）
- 是否同步更新了文档与测试


## 通用红线（本项目）

1. `packages/core` 与 `server` **零第三方依赖** —— 只用 Node22 内置模块
2. 三端只消费 `/api/*`，禁止直接 import 内核
3. 代码改了必须同步文档与测试
4. 前端开发由崔志帅本人执行，Agent 只提建议不改前端代码
