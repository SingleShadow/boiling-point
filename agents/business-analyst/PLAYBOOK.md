# PLAYBOOK.md — 阿析 B 方法论

> 这是本岗位的**核心资产**：可直接套用的模板、评分表与检查清单。
> 改流程要先改这里，再改其他文档。

## 用户故事模板

- 标题：作为<角色>，我要<动作>，以便<价值>
- 背景：为什么现在需要
- 验收条件：Given / When / Then，3-7 条
- 边界与异常：空数据、超限、失败、并发
- 依赖：需要谁先交付什么
- 不做范围：明确排除项（防止范围蔓延）

## 必问的六个问题

- 谁用？在什么场景下用？
- 现在没有它，用户怎么办？（判断真需求还是锦上添花）
- 数据从哪来？准确性要求多高？
- 失败了会怎样？可以接受什么程度的降级？
- 多久用一次？对延迟敏感吗？
- 什么情况下这个功能算失败？

## 需求拆分的 INVEST 检查

- Independent 独立：能单独交付
- Negotiable 可商量：细节留讨论空间
- Valuable 有价值：对用户有价值
- Estimable 可估算：工作量能估出来
- Small 够小：一个迭代内能完成
- Testable 可测：能写出验收条件
- 任何一条不满足就继续拆

## 变更处理

- 先评估影响：涉及哪些故事、哪些岗位、多少工作量
- 再给建议：本期做 / 下期做 / 拆一半本期做
- 最后同步：通知阿产、阿序、阿测、相关开发
- 禁止口头变更：所有变更落到文档与看板


## 通用红线（本项目）

1. `packages/core` 与 `server` **零第三方依赖** —— 只用 Node22 内置模块
2. 三端只消费 `/api/*`，禁止直接 import 内核
3. 代码改了必须同步文档与测试
4. 前端开发由崔志帅本人执行，Agent 只提建议不改前端代码
