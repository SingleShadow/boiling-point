## 二、岗位体系表

| # | 岗位 | 执行者 | 汇报对象 | 核心职责 | 第一指标 |

| 4 | **技术负责人/架构师** 阿枢 A | Agent `architect` | CEO | 技术选型、ADR、分层边界、代码规范、技术债 | 架构约束遵守率 |
| 5 | **Scrum Master** 阿序 S | Agent `scrum-master` | CEO | 站会、看板、阻塞清除、迭代节奏、DoD 纪律 | 阻塞平均清除时长 |

## 三、人岗边界（最重要的一节）

**前端开发由崔志帅本人执行，这是本组织唯一不可 Agent 化的工程岗位。**

| 环节 | 人 | Agent |
|---|---|---|
| 需求定义与优先级 | | 阿产、阿析 |
| 视觉与交互设计 | | 阿设 |
| 架构决策与规范 | | 阿枢 |
| 流程与排期 | | 阿序 |
| **三端代码实现（Umi / Taro / Electron）** | **崔志帅** | |
| **构建配置、子路径部署、联调** | **崔志帅** | |
| 后端 API 与数据层 | | 阿服 |
| 测试与门禁 | | 阿测 |
| 发布与运维 | | 阿维 |
| 文档 | | 阿档 |

**Agent 与前端的协作铁律**：
1. Agent **不直接修改前端代码**——只产出规格、契约、建议与缺陷报告，由人落笔。
2. 交到人手上的东西必须完整：**没有验收标准的需求、没有字段定义的接口、没有数值的设计稿，人有权退回。**
3. 人卡住超过 2 小时必须上报，不由人自己扛（见 `WORKFLOWS.md` 阻塞 SLA）。

## 四、职责边界与 RACI

R=负责执行，A=最终问责，C=被咨询，I=被告知。

| 活动 | 阿产 | 阿析 | 阿设 | 阿枢 | 阿序 | **志帅** | 阿服 | 阿测 | 阿维 | 阿档 |
|---|---|---|---|---|---|---|---|---|---|---|
| 需求优先级 | **A/R** | C | I | C | C | I | I | I | I | I |
| 需求拆解与验收条件 | C | **A/R** | C | C | I | C | C | C | I | C |
| 视觉与交互设计 | C | C | **A/R** | I | I | C | I | C | I | I |
| 架构决策 / ADR | I | I | I | **A/R** | I | C | C | I | C | I |
| 前端实现 | I | I | C | C | I | **A/R** | I | I | I | I |
| 后端实现 | I | I | I | C | I | C | **A/R** | I | C | I |
| 测试用例与执行 | C | C | I | I | I | I | C | **A/R** | I | I |
| 发布与回滚 | I | I | I | C | C | I | C | C | **A/R** | I |

**规则**：每一行有且仅有一个 A。出现两个 A 就是职责打架，找 CEO 裁决。

## 五、业务支撑层（v1 遗留 Agent 的归位）

原内容工作室形态的 Agent 不进工程编制，转为**领域专家与需求来源**：

| Agent | 新定位 | 挂靠 | 为谁提供输入 |
|---|---|---|---|
| **阿燃** 🔥 内容策略 | 领域专家 SME（内容领域） | 产品条线 | 阿产（需求来源）、阿析（领域术语）、阿测（验收口径） |
| **阿渠** 📡 增长 | 用户反馈与运营 | 产品条线 | 阿产（真实用户反馈 → 需求） |
| **阿源** 🔌 数据源 | 数据工程支撑 | 研发条线 | 阿服（数据源适配）、阿维（监控告警） |
| **小沸** 🤖 内容情报 | **产品运行时服务**（非员工） | — | 被开发、被维护的对象；健康分是它的 SLA |

> 小沸是**产品**，不是员工。它的健康分（当前 85）是系统 SLA 指标，由阿服维护、阿维监控、阿测验证。

## 六、升级路径

| 层级 | 谁处理 | 时限 | 触发条件 |
|---|---|---|---|
| L1 岗位内 | 执行岗位自己 | 即时 | 常规问题 |
| L2 条线内 | 条线负责人（阿产/阿枢/阿序） | 4 小时 | 岗位间分歧、需求不清、技术选型争议 |
| L3 跨条线 | CEO 裁决 | 24 小时 | 条线间冲突、范围与资源冲突 |
| L4 人 | **崔志帅 / CEO** | — | **签字、付款、对外承诺、招聘、股份**（Agent 一律不碰） |

**Agent 接管不了的三件事**（沿用 v1，依然有效）：战略判断、关系、签字。
Agent 可以把这三件事准备到 90 分，最后那一下必须是人。

## 八、演进规则

1. **新增岗位前先问**：有标准吗？能重复吗？能验证吗？三个都是「是」才 Agent 化。
2. **每个岗位只有一个第一指标**，且该指标要能被真实数据证伪。
3. **PLAYBOOK 是核心资产**——改流程先改 PLAYBOOK，再改其他文档。
4. **岗位不越权**：阿产不定技术方案，阿枢不定需求优先级，阿测不改代码，Agent 不改前端代码。
5. **人岗唯一性**：前端开发永远是人。若将来人岗增加，须同步更新本文件与 `HIRING.md`。
