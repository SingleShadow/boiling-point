# 沸点创意 · 研发协作流程规则

> v1 · 2026-10-12 · 维护人：阿序（Scrum Master）· 批准：CEO
> 本文是**可直接复制执行**的流程与模板。岗位定义见 `ORG.md`。

## 一、节奏总览

| 周期 | 活动 | 时间 | 主持 | 产出物 |
|---|---|---|---|---|
| 每日 | 站会 | 09:30（15 分钟硬上限） | 阿序 | 站会记录、当日任务清单、阻塞台账 |
| 每日 | 进度更新 | 随时（状态变化即更新） | 各岗位 | 看板状态 |
| 每日 | 收工同步 | 18:30 | 阿序 | 当日完成/未完成、次日优先级 |
| 每周一 | 迭代规划 | 10:00（45 分钟） | 阿产 + 阿序 | 迭代范围、故事卡、优先级评分 |
| 每两周（周五） | 迭代评审 | 15:00 | 阿产 | 演示清单、验收结论 |
| 每两周（周五） | 迭代回顾 | 16:00 | 阿序 | 回顾报告、改进项（只改一件） |
| 每月 | 里程碑复盘 | 月末 | CEO | 里程碑状态、风险台账 |

**迭代长度：2 周。** 缓冲 20%（1 个工作日）留给技术债与突发。

## 二、每日流程

### 2.1 晨会（09:30，15 分钟）

**三问，每人 60 秒**：

1. 昨天完成了什么（只说结果，不说过程）
2. 今天要做什么（说具体产出物，不说"继续做"）
3. 有什么阻塞（没有就说没有）

**纪律**：
- 不展开技术讨论——需要讨论的会后立即开小会，不占站会时间
- 缺席岗位由阿序代记状态并事后同步
- 超过 15 分钟视为流程失败，阿序在回顾里复盘原因

**主持人（阿序）会后 5 分钟内产出**：当日任务清单 + 阻塞台账，同步全员。

### 2.2 当日任务清单与优先级

每个任务必须满足**可开工三要素**，缺一不可：

| 要素 | 由谁提供 | 缺失时怎么办 |
|---|---|---|
| 用户故事（一句话价值） | 阿析 | 退回阿析 |
| 验收标准（3-7 条，可判定） | 阿产 | **退回阿产，不许猜** |
| 技术方案/约束（涉及架构时） | 阿枢 | 退回阿枢 |

**优先级四档**（阿产排序，阿序执行）：

| 档 | 含义 | 处理 |
|---|---|---|
| **P0** | 阻断（全组停工、线上故障） | 立即做，其他全停 |
| **P1** | 本迭代必须完成 | 优先排 |
| **P2** | 本迭代尽量完成 | 有余力再做 |
| **P3** | 待办池 | 不进迭代 |

**WIP 上限**：「进行中」列最多 3 项。超了说明该清阻塞，不是该开工。

### 2.3 执行中的进度更新

- **状态变化即时更新看板**，不等站会
- 看板列：`待办 → 就绪 → 进行中 → 待验收 → 完成`
- **「就绪」列不许跳**：没有验收标准不许进「进行中」
- 预计延期时**立即**上报，不要等到站会才说

### 2.4 跨岗位交接

| 交接 | 交出什么 | 交给谁 | 验收方式 |
|---|---|---|---|
| 需求 → 设计 | 故事 + 用户场景 | 阿设 | 阿设确认场景完整 |
| 设计 → 前端 | 设计规格（**数值化**：尺寸/色值/间距/状态） | 志帅 | 人确认可实施 |
| 需求 → 后端 | 契约要求（字段/行为） | 阿服 | 阿服出 API 契约 |
| 后端 → 前端 | API 契约（路径/字段/错误码） | 志帅 | 人确认字段齐全 |
| 前端/后端 → QA | 自测通过的实现 + 自测结论 | 阿测 | 阿测按验收标准验 |
| QA → 发布 | 门禁结论（通过/不通过） | 阿维 | 阿维见结论才发 |
| 任意 → 文档 | 变更点 | 阿档 | 阿档同步后确认 |

**交接铁律**：**交付物不完整 = 没交付。** 收到不完整的东西要退回，不要自己补全再往下传——那会让问题消失在链条里。

### 2.5 阻塞上报与升级

| 级别 | 判定 | 响应时限 | 升级路径 |
|---|---|---|---|
| **P0** | 全组停工 / 线上故障 | **30 分钟** | 立即报 CEO |
| **P1** | 某岗位停工 | **4 小时** | 阿序推动 → 超时自动报 CEO |
| **P2** | 进度受影响，有绕行 | 本迭代内 | 站会跟踪 |

**阻塞单必填四项**：负责人、原因、预计解除时间、升级对象。
**任何人（包括崔志帅）卡住超 2 小时必须上报**，不允许自己扛。

## 三、每周与迭代流程

### 3.1 迭代规划（周一 10:00，45 分钟）

1. 阿产按 RICE 排序候选需求，公开评分依据
2. 阿枢给出每项的技术代价与风险（不做/代价高要明说）
3. 团队共同确定本迭代容量（含 20% 缓冲）
4. 逐项确认验收标准齐全——**不齐全的进不了迭代**
5. 阿序锁定范围并公告

**产出**：迭代范围清单（含每项的负责人、优先级、验收标准链接）

### 3.2 迭代评审（周五 15:00）

- 逐条演示本迭代完成项，**按验收标准逐条判定通过/不通过**
- 未完成项说明原因并决定：顺延 / 拆小 / 砍掉
- 阿产更新路线图

**产出**：演示清单 + 验收结论 + 范围调整记录

### 3.3 迭代回顾（周五 16:00）

**四问**：
1. 这个迭代哪些做对了，要保持
2. 哪些做错了，**根因是什么（追机制，不追责）**
3. 下个迭代改**一件**具体的事（只改一件）
4. 上次改的事做到了吗

**产出**：回顾报告 + 一个改进项（进下个迭代任务清单）

## 四、里程碑与风险跟踪

### 4.1 里程碑定义

| 字段 | 说明 |
|---|---|
| 名称 | 一句话说清达成什么状态 |
| 日期 | 目标日期 |
| 验收条件 | 可判定的完成标准 |
| 负责人 | 唯一 |
| 状态 | 未开始 / 进行中 / 有风险 / 达成 / 延期 |

**风险状态判定**：关键路径上有 P1 阻塞超 4 小时，或完成度落后计划 20% 以上 → 自动置为「有风险」。

### 4.2 风险台账

| 字段 | 说明 |
|---|---|
| 风险描述 | 可能影响什么目标 |
| 概率 × 影响 | 各 1-5 分，乘积 ≥ 15 必须上报 CEO |
| 责任人 | 唯一 |
| 应对 | 规避 / 减轻 / 接受 / 转移 |
| 状态 | 开放 / 已缓解 / 已关闭 |

**阿序每周更新一次**，月会由 CEO 复核。

## 五、产出物模板（可直接复制）

### 5.1 每日站会记录

```markdown
# 站会记录 YYYY-MM-DD

## 昨日完成
- [岗位] 产出物（状态：完成/部分完成）

## 今日计划
- [岗位] 产出物（优先级 P0/P1/P2）

## 阻塞
| 级别 | 描述 | 负责人 | 预计解除 | 升级对象 |
|---|---|---|---|---|
| P1 | xxx | 阿服 | 今日 16:00 | 阿序 |

## 当日任务清单
| # | 任务 | 负责人 | 优先级 | 验收标准 | 状态 |
|---|---|---|---|---|---|
| 1 | xxx | 志帅 | P1 | 见 story-12 | 进行中 |
```

### 5.2 用户故事卡

```markdown
# STORY-<N> <标题>

作为 <角色>，我要 <动作>，以便 <价值>

## 背景
为什么现在需要

## 验收标准
1. Given ... When ... Then ...
2. （边界）...
3. （异常）...

## 不做范围
- 明确排除项

## 依赖
- 需要谁先交付什么
```

### 5.3 阻塞单

```markdown
# BLOCK-<N>

- 级别：P0 / P1 / P2
- 阻塞对象：谁被卡住
- 原因：一句话
- 已尝试：做过什么
- 需要谁做什么：明确请求
- 预计解除：时间
- 升级对象：若超时找谁
```

### 5.4 缺陷报告

```markdown
# BUG-<N> <模块> <现象>

- 级别：P0/P1/P2/P3
- 环境：版本 / 数据源模式 / 端
- 复现步骤：1-2-3
- 期望结果 vs 实际结果
- 证据：截图 / 日志 / 请求响应
```

### 5.5 发布门禁结论

```markdown
# 发布门禁 <版本> <日期>

- [ ] 全量单测通过
- [ ] 新增用例通过，无回归失败
- [ ] P0/P1 缺陷清零
- [ ] 接口冒烟全绿
- [ ] 文档已同步
- [ ] 回滚方案就绪

结论：通过 / 不通过 —— 阿测 <签名>
```

## 六、本项目常用命令（交接时直接引用）

| 场景 | 命令 |
|---|---|
| 数据源自检 | `npm run datasource:check` |
| 全量测试 | `npm test` |
| 启动服务 | `node server/src/index.js`（端口 8787） |
| Agent 值守一次 | `npm run agent:run` |
| 查看健康分 | `curl localhost:8787/api/agent/status` |
| 回溯历史数据 | `curl -X POST localhost:8787/api/backfill -H "Content-Type: application/json" -d '{"days":7}'` |
| 重建岗位包 | `python agents/scaffold.py && python agents/build.py` |

**已知环境约束**（踩过坑，别重复踩）：
- 改前端产物或 Agent 逻辑后**必须重启服务**（`STATIC_MAP` 在启动时解析 dist 目录）
- Bash 工具需先 `export PATH="/usr/bin:/bin:/usr/local/bin:$PATH"`
- Windows 按端口杀进程用 PowerShell，不要用 Bash
- 内核与 server **零第三方依赖**，禁止引入 npm 包

## 七、流程纪律（违反即进回顾）

1. 站会不超 15 分钟
2. 无验收标准不许开工
3. 阻塞不隐瞒，按 SLA 上报
4. 交付物不完整要退回，不替别人补全
5. WIP 不超 3
6. 代码改了必须同步文档与测试
7. 涉及签字、付款、对外承诺——**一律转人，Agent 不碰**
