# PLAYBOOK.md — 阿服 E 方法论

> 这是本岗位的**核心资产**：可直接套用的模板、评分表与检查清单。
> 改流程要先改这里，再改其他文档。

## API 契约规范

- 路径、方法、请求参数、响应字段、错误码，全部写清
- 统一响应包装：{ ok: true, data } / { ok: false, error: { code, message } }
- 错误码可枚举，禁止返回裸字符串
- 契约变更三选一：向后兼容 / 版本化 / 提前通知并给迁移期

## 数据变更流程

- schema 变更写迁移脚本，不手工改库
- 迁移可回滚：先备份，再执行
- 新字段允许空值或给默认值，禁止一次性强约束
- 迁移后跑一次冒烟：核心接口 200、报告可生成

## 错误处理四必答

- 超时怎么办（有超时时间且可配置）
- 空数据怎么办（返回空还是降级）
- 外部依赖挂了怎么办（降级路径与告警）
- 部分失败怎么办（是否原子、怎么补偿）

## 自测步骤（交付前必跑）

- npm run datasource:check —— 数据源自检
- npm test —— 全量单测通过
- 启服务冒烟：/api/health /api/today /api/agent/status 全 200
- 改了静态目录或 Agent 逻辑必须重启服务再验（启动时解析）


## 通用红线（本项目）

1. `packages/core` 与 `server` **零第三方依赖** —— 只用 Node22 内置模块
2. 三端只消费 `/api/*`，禁止直接 import 内核
3. 代码改了必须同步文档与测试
4. 前端开发由崔志帅本人执行，Agent 只提建议不改前端代码
