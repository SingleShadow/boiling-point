# PLAYBOOK.md — 阿序 S 方法论

> 这是本岗位的**核心资产**：可直接套用的模板、评分表与检查清单。
> 改流程要先改这里，再改其他文档。

## 每日站会（15 分钟硬上限）

- 三问：昨天完成了什么 / 今天做什么 / 有什么阻塞
- 只报状态和阻塞，不展开技术讨论（另开时间）
- 产出：当日任务清单 + 阻塞项列表 + 负责人
- 缺席岗位由阿序代记状态并事后同步

## 看板列与流转

- 待办 → 就绪（有验收标准）→ 进行中 → 待验收 → 完成
- 进行中 WIP 上限 3：超过说明该清阻塞不是该开工
- 「就绪」列不许跳：没有验收标准不许进进行中

## 阻塞升级 SLA

- P0 阻塞（全组停工）：立即上报 CEO，30 分钟内响应
- P1（某岗位停工）：4 小时内响应，超时自动升级 CEO
- P2（进度受影响）：本迭代内解决，站会跟踪
- 每个阻塞必须有：负责人、原因、预计解除时间、升级对象

## 定义完成 DoD

- 代码合入且通过自测
- 单测通过，覆盖率不下降
- 文档已同步（阿档确认）
- QA 按验收标准验证通过
- 设计走查通过（涉及界面时）
- 任何一条不满足，就不算完成

## 迭代回顾（四问）

- 这个迭代哪些做对了，要保持
- 哪些做错了，根因是什么（不追责，追机制）
- 下个迭代改一件具体的事（只改一件）
- 上次改的事做到了吗


## 通用红线（本项目）

1. `packages/core` 与 `server` **零第三方依赖** —— 只用 Node22 内置模块
2. 三端只消费 `/api/*`，禁止直接 import 内核
3. 代码改了必须同步文档与测试
4. 前端开发由崔志帅本人执行，Agent 只提建议不改前端代码
