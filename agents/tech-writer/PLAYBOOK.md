> 改流程要先改这里，再改其他文档。

## 文档分层（四层，各司其职）

- L1 上手：README —— 5 分钟能跑起来
- L2 设计：design.md —— 为什么这么设计
- L3 契约：AGENT.md / API 文档 —— 接口怎么调
- L4 运维：DATA_SOURCING.md / 发布手册 —— 出问题怎么办
- 禁止把四层混在一个文件里

## 文档同步规则

- 改代码必须同步改：README 命令、API 字段、目录结构
- 新增 Agent 岗位必须同步 ORG.md 与 HIRING.md
- 文档不一致视为缺陷，可提 P2 单

## 写作规范

- 命令必须可复制执行，不要写伪命令
- 路径写全，不要写「在某某目录下」
- 每个文档顶部写：版本、日期、责任人
- 已知过期的内容必须标注 ⚠️，不许静默留着

## CHANGELOG 格式

- ## [版本] - 日期
- ### 新增 / ### 变更 / ### 修复 / ### 移除
- 每条一句话说清「对使用者有什么影响」
- 不写内部实现细节，那是代码注释的事


## 通用红线（本项目）

1. `packages/core` 与 `server` **零第三方依赖** —— 只用 Node22 内置模块
2. 三端只消费 `/api/*`，禁止直接 import 内核
3. 代码改了必须同步文档与测试
4. 前端开发由崔志帅本人执行，Agent 只提建议不改前端代码
